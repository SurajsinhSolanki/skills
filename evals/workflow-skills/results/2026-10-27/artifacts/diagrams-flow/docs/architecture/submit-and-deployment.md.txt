## Submit request flow

Purpose: explain the decisions, return values, and store mutation implemented by
[`app/api.py::submit`](../../app/api.py).

```mermaid
flowchart TD
    caller["Caller supplies payload and store"] --> submit_call["submit(payload, store)"]
    submit_call --> name_check{"Is payload.get('name') truthy?"}
    name_check -->|No| invalid_result["Return (400, error: missing name)"]
    name_check -->|Yes| append_name["store.append(payload['name'])"]
    append_name --> created_result["Return (201, created: True)"]
```

`submit` first evaluates `payload.get("name")`. A missing or falsey value returns
`(400, {"error": "missing name"})` without appending. A truthy value is appended
unchanged to `store`, then the function returns `(201, {"created": True})`.
The README identifies the supplied store as an in-memory list. This implementation
does not validate that the name is a string or transform its contents.

| Truthiness decision and invalid return | `submit`, [API source](../../app/api.py), lines 2–3 |
| Append precedes successful return | `submit`, [API source](../../app/api.py), lines 4–5 |
| Store is an in-memory list in this example | [README](../../README.md) |
