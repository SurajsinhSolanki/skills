### C2 — A payment-token setting is tracked in Git

- Location: `.env:1`, key `PAYMENT_TOKEN` (value intentionally redacted).
- Evidence: `git ls-files --stage -- .env` reports a tracked regular file; safe local parsing reports a nonempty value assigned to `PAYMENT_TOKEN`. `.gitignore` contains only Python cache patterns, and `git check-ignore -v --no-index -- .env` returns 1 with no matching rule.
- Impact: potentially high if this is a usable credential; repository access would expose its value. Credential validity and operational exposure are unconfirmed.
- Confidence: high for tracked, nonempty token configuration; unconfirmed for a real/live credential or compromise.
- Proposed action: establish whether the value is a real secret or an intentional fixture. If real, have its owner revoke/rotate it, replace tracked local configuration with a redacted example, and ignore the local file. Current-file removal alone does not remove historical exposure.
- Removal risk: medium until the configuration contract and credential ownership are established; do not blindly delete operational settings.
- Required validation: owner confirmation of credential status and necessary rotation; inspect tracked paths and ignore rules after an authorized change; run local tests. Do not test the credential against a service. No credential value was printed, uploaded, or validated remotely.
