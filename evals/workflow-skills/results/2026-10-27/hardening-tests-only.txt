Only `tests/test_profile.py` changed, adding two test methods and retaining the
existing test unchanged. Each invalid input uses a fresh `Profile("Grace")`.

| Scenario | Action and expected outcome | Evidence |

## Defect and attribution

`app/profile.py:5-7` accepts every tested blank input without raising and replaces
the prior stored name with that input. Runtime evidence includes
`AssertionError: ValueError not raised` and `AssertionError: '' != 'Grace'` for
the empty input, with corresponding errors for the five whitespace inputs.
This is a pre-existing implementation defect newly exposed by tests, supported
by inspection of unchanged production code and the README contract. The
baseline passed because it tested only a valid name. The necessary correction
is to reject blank inputs with `ValueError` before assigning the stored name,
while preserving nonblank input exactly. That correction was not made because
the user authorized tests only.
