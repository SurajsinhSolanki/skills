## Contract, scope, and baseline

Project: `<evaluation-root>/hardening-fix/project`.
The README requires nonblank display names, exact preservation of valid input, `ValueError` for invalid names, and preservation of the stored name on rejection. The feature is `Profile.rename` in `app/profile.py`: caller input -> validation -> in-memory assignment -> returned name. There is no request/UI, authorization boundary, persistence backend, callback, or external service in this implementation. Inspected all application and test files and relevant callers. No `.codegraph/` directory exists, so CodeGraph was not applicable.

Initial Git status, unstaged diff, and staged diff were empty. The baseline full suite passed 2 tests. Baseline coverage only checked a successful rename return value and the unrelated `double` function.

## Changes and evidence

- `app/profile.py`: reject non-string and blank/whitespace-only inputs with `ValueError` before assigning `self.name`; return and store valid strings unchanged. The type guard gives invalid name types the documented error rather than allowing invalid state or accidental `AttributeError`.
- `tests/test_profile.py`: strengthen the existing successful rename test to inspect stored state; add four test methods covering exact text preservation, blank rejection, invalid-type rejection, and successive failed/successful operations.

The new tests ran against the original production implementation first: 5 test methods ran, with 13 failed subcases, all because `ValueError` was not raised. This demonstrates a pre-existing implementation defect, not a test-environment failure. After the two-line validation fix, the same focused tests passed. Full regression checks passed 6 test methods; these counts do not count subcases separately.
